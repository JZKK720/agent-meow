# Omnigent → agent-meow Rebrand Gap Analysis & Recommendation

**Written against commit**: `21a3e2052` (2026-08-26)
**Analysis type**: Deep-dive rebrand gap audit (read-only, no code changes)

---

## Executive Summary

The rebrand from "omnigent" to "agent-meow" is **~20% complete**. The Python
*import module* was renamed (`omnigent/` → `agent_meow/`), but the PyPI
*distribution names*, *SDK module directories*, *environment variables*, *CLI
entry points*, *frontend bridge names*, *CSS variables*, *IPC channels*, *HTTP
headers*, *database schema*, and *wire-protocol sentinels* all still say
"omnigent." A prior attempt to complete the rename reached `0.5.0.dev0`
(see `agent_meow.egg-info/PKG-INFO`: `Name: agent-meow`, author "智方云
(Cubecloud)") but was abandoned and the upstream `omnigent` metadata
reasserted itself.

**Total "omnigent" references across the codebase**: ~1,500+ across ~200 files
(excluding `web/electron/embedded-python/` vendored copies and `.egg-info`
generated metadata).

## Active Risks (bugs lurking in the gap right now)

### Risk 1: `OMNIGENT_EXECUTOR_TYPE` split-brain (HIGH)
- `agent_meow/spec/omnigent.py:75` defines `OMNIGENT_EXECUTOR_TYPE = "agent-meow"`
- `agent_meow/spec/_omnigent_compat.py:65` defines `OMNIGENT_EXECUTOR_TYPE = "omnigent"`
- Callers import from `_omnigent_compat` (the live value is `"omnigent"`)
- The `"agent-meow"` value in `omnigent.py` appears unused
- **Impact**: If someone imports from the wrong module, executor type
  matching silently fails. This is exactly the label-key split-brain trap
  documented in user memory.

### Risk 2: Deep-link scheme conflict (MEDIUM)
- `package.json` declares `protocols[0].schemes = ["agent-meow"]`
- `main.js` handles `omnigent://` deep links
- `agent-meow://` deep links may not be handled at all

### Risk 3: `setup.py` writes to stale paths (MEDIUM)
- `setup.py` writes to `omnigent/_build_info.py` and `omnigent/resources/...`
- The `omnigent/` directory only contains the compat shim (`__init__.py` +
  `_build_info.py`) — it does NOT have `resources/` or `server/`
- Build-time file copying may silently fail or write to wrong locations

### Risk 4: Stale `agent_meow.egg-info` (LOW)
- Shows `Version: 0.5.0.dev0` and `agent-meow-client==0.5.0.dev0` deps
- If pip reads this instead of `omnigent.egg-info`, it gets wrong metadata
- The `embed_python.js` script deletes `omnigent.egg-info` but NOT
  `agent_meow.egg-info`

## Recommendation: Three Options

### Option A: Complete the full rebrand (RECOMMENDED)

**What**: Rename every "omnigent" reference to "agent-meow" across all layers.

**Effort**: L (Large) — ~200 files, ~1,500+ replacements, multi-layer
coordination, breaking changes (env vars, DB schema, wire protocol, storage
keys, deep-link scheme).

**Phasing** (4 sequential plans):
1. **Plan 031**: Python distribution metadata + SDK module dirs + imports
   (pyproject.toml × 4, setup.py, update_versions.py, embed_python.js,
   rename `omnigent_client/` → `agent_meow_client/`, `omnigent_ui_sdk/` →
   `agent_meow_ui_sdk/`, `omnigent_slack/` → `agent_meow_slack/`, update all
   36 import sites + 438 test references, delete `omnigent/__init__.py` shim)
2. **Plan 032**: Python internal symbols + env vars + DB migration
   (`OMNIGENT_*` → `AGENT_MEOW_*` across 77 files, `OmnigentError` →
   `AgentMeowError`, `OmnigentClient` → `AgentMeowClient`, DB migration for
   table + column rename, `OMNIGENT_INTERNAL_WS_ORIGIN` sentinel update,
   fix `OMNIGENT_EXECUTOR_TYPE` split-brain)
3. **Plan 033**: Frontend bridge + CSS + IPC + HTTP headers
   (`window.omnigent*` → `window.agentMeow*`, `--omnigent-*` →
   `--agent-meow-*`, `omnigent:*` IPC → `agent-meow:*`, `X-Omnigent-Client`
   → `X-Agent-Meow-Client`, storage key migration, user-facing strings)
4. **Plan 034**: Electron shell + deep-link scheme + cleanup
   (`omnigent://` → `agent-meow://`, `omnigent_cli.js` → `agent_meow_cli.js`,
   macOS permission text, update overlay title, README, tests, delete
   `omnigent.egg-info`)

**Pros**:
- Eliminates all split-brain risks
- Clean, single-identity codebase
- No compat shim maintenance
- User-facing strings all say "agent-meow"

**Cons**:
- Large effort (2-3 days of focused work)
- Breaking changes for existing users (env vars, DB schema, storage keys,
  deep-link scheme) — requires migration scripts + backward-compat shims
- Must be done in one coordinated push (partial rename creates MORE
  split-brain risk, per the label-key split-brain trap in user memory)
- DB migration is irreversible without a downgrade path

**When to choose**: When the fork is the canonical distribution and no
upstream sync is needed (which is the stated policy). This is the correct
long-term answer.

### Option B: Pragmatic partial — fix only the active risks

**What**: Fix the 4 active risks without doing the full rename.

**Effort**: M (Medium) — ~10 files, targeted fixes.

1. Fix `OMNIGENT_EXECUTOR_TYPE` split-brain: pick one value, delete the other
2. Fix deep-link scheme: make `main.js` handle `agent-meow://` (keep
   `omnigent://` as alias for backward compat)
3. Fix `setup.py` stale paths: `omnigent/` → `agent_meow/`
4. Delete stale `agent_meow.egg-info` (or regenerate it with correct version)
5. Update `embed_python.js` to also clean `agent_meow.egg-info`

**Pros**:
- Fast (hours, not days)
- No breaking changes
- Eliminates the bugs that could bite today

**Cons**:
- Leaves ~1,490 "omnigent" references in the codebase
- The identity split persists — future developers will be confused
- The compat shim stays forever
- User-facing strings still say "Omnigent"

**When to choose**: When shipping the v0.9.0 Electron app is the priority and
the full rebrand can wait for a dedicated session.

### Option C: Status quo — document and defer

**What**: Do nothing now. Record the gap in memory and plans. Address it in
a future dedicated rebrand sprint.

**Effort**: S (Small) — this document.

**Pros**:
- Zero risk of introducing new bugs
- No breaking changes

**Cons**:
- Active risks (split-brain, stale paths) remain
- Technical debt grows with every commit that adds new "omnigent" references
- The `agent_meow.egg-info` stale metadata could cause pip confusion

**When to choose**: Never as a permanent state. Only as a deliberate
short-term hold.

---

## Verdict

**Option A (full rebrand) is the correct recommendation**, given:
1. The fork policy explicitly states this is a completed rebrand with no
   upstream sync — there is no reason to keep the "omnigent" identity.
2. The prior attempt reached `0.5.0.dev0` and was abandoned, leaving
   stale metadata that could cause pip/build confusion.
3. The `OMNIGENT_EXECUTOR_TYPE` split-brain is an active bug risk.
4. The deep-link scheme conflict is an active bug.
5. User-facing strings still say "Omnigent" in the Electron app.

However, **Option B should be executed first** as a fast stabilization pass
before the full rebrand, to eliminate the active risks without the breaking
changes. Then Option A follows as the comprehensive fix.

**Recommended execution order**:
1. **Now**: Option B (fix active risks) — ~2 hours, no breaking changes
2. **Next session**: Plan 031 (Python metadata + SDK dirs) — the foundation
3. **Then**: Plan 032 (internal symbols + env vars + DB) — depends on 031
4. **Then**: Plan 033 (frontend) — depends on 031 (server contract names)
5. **Finally**: Plan 034 (Electron + cleanup) — depends on 033

**Do NOT attempt the full rebrand in a single commit** — the label-key
split-brain trap (documented in user memory) means a partial rename across
one layer but not another creates MORE bugs than it fixes. Each plan must
land complete and verified before the next begins.
